# Локальная репетиция den на RTX 3070: что мы делали, шаг за шагом

Дата: 7–8 октября 2026. Машина: Windows + WSL2 (Ubuntu 26.04.1), NVIDIA GeForce RTX 3070 8 GB, 15 GB RAM для WSL.
Модель: `qwen3.5-0.8b`. Данные: не больше 1000 записей из каждого файла (`LOCAL_N=1000`).
Инструкция, по которой шли: `docs/local-gpu.md`. Логи: `runs/local/logs/`.

**Итог: репетиция пройдена.** Все гейты прошли, все стадии обучились, сохранились и прошли merge; `nan` и нехватки
памяти не было. Цифры качества здесь ничего не значат: это маленькая модель на малой части данных. Репетиция
проверяет, что процесс работает, а не насколько хороша модель.

## Шаг 2. Установка: код, окружение, модель, данные

```bash
sudo apt install -y build-essential                                  # компилятор для Triton
curl -LsSf https://astral.sh/uv/install.sh | sh && source ~/.local/bin/env
make local-setup 2>&1 | tee ~/local-setup.log
export UV_NO_SYNC=1 && echo 'export UV_NO_SYNC=1' >> ~/.bashrc
```

`make local-setup` по очереди сделал:
1. `setup-gpu`: Python 3.12, torch 2.14.1 (CUDA 13), transformers 5.17, flash-linear-attention 0.5.2, затем Unsloth
   2026.10.2 поверх, не трогая torch и transformers (`bf16 True`, без строки `BAD`).
2. `model`: скачал `qwen3.5-0.8b` (1.6 GB) и записал отпечатки её файлов в `locks/models.json` (раньше их там не было).
3. `data-download`: `data/` с `a1i6ek/den-datasets` + пересборка файлов, которые нельзя выкладывать по лицензиям.
   Закончился строкой `ok, every file matches` за 8.4 мин.
4. `data-check`: токенизировал данные репетиции:

   | Набор | Записей | Токенов (медиана / max / всего) | Пропущено |
   |---|---|---|---|
   | train | 6586 | 180 / 6058 / 3.1M | 0 |
   | dev | 1468 | 111 / 858 / 0.3M | 0 |
   | calib | 1148 | 120 / 815 / 0.2M | 0 |

5. `local-doctor`: все проверки `ok`, включая «GPU memory fits qwen3.5-0.8b in bf16 (~3.6 GB)».

В логе установки ошибок не было. Только безвредные предупреждения: компилятор (`_POSIX_C_SOURCE`) и «unauthenticated
requests to the HF Hub» (не делали `hf auth login`, скачивание всё равно прошло).

## Шаг 3. Гейты: может ли машина вообще обучать (около 15 мин)

```bash
make local-gates
```

| Гейт | Что проверяет | Результат |
|---|---|---|
| 3.1 тесты CUDA | Unsloth грузит модель в bf16, LoRA только на текстовой части, один шаг двигает адаптеры и голову | `3 passed` за 94 с |
| 3.2 `den overfit` | LoRA + голова выучивают 100 реальных строк | `PASS` за 4.7 мин |
| 3.3 `den train --overfit 100` | то же через настоящий цикл обучения | acc 1.0000, loss с ~1.3 до ~1e-7 |

Подробности 3.2 (`overfit-lora.json`): точность 1.0 на 100 строках, результат детерминирован, `content_agreement`
1.0 (голова читает содержание вариантов, а не их позицию; случайный уровень 0.18), замена правильного варианта
снижает его вероятность в 100% случаев. Пик памяти 2.5 GB. 186 LoRA-модулей — это норма для 0.8B (24 слоя; у 4B
32 слоя и 248 модулей).

В 3.3 калибровка дала T = 13.1. Для overfit-прогона это ожидаемо (модель выучила строки наизусть и очень уверена), на
гейт не влияет.

## Шаг 4. Обучение обоих раундов в малом масштабе (около 1 ч 50 мин)

```bash
make local-train
nvidia-smi dmon -s um          # во втором окне: загрузка и память GPU раз в секунду
```

Те же команды, что на H100 (`train-round1`, затем `train-round2`), но с `--limit 1000 --batch 1 --accum 8`.
Каждая следующая стадия начинается с финальных весов предыдущей (`init from ...`).

| Стадия | Данные | Шагов | dev | acc | NLL после T | ECE после T | T | Лучший шаг |
|---|---|---|---|---|---|---|---|---|
| 1-base | `core`, 2 эпохи | 360 | core | 0.757 | 0.640 | 0.026 | 1.78 | 350 |
| 2-dates | `dates-unknowable` + повтор `core` | 282 | core | 0.766 | 0.615 | 0.034 | 1.96 | 50 |
| 3-documents | `documents` + повтор | 339 | documents + core | 0.786 | 0.617 | 0.040 | 2.54 | 100 |
| 4-skills (+ merge) | `skills` + `devtools` + повтор | 517 | skills + devtools + core | 0.617 | 0.858 | 0.028 | 2.30 | 150 |
| round2 (+ merge) | по 100 из каждого публичного источника + по 100 из каждого набора Kev | 316 | все четыре | 0.657 | 0.782 | 0.014 | 1.75 | 50 |

Строки между собой сравнивать нельзя: у стадий разные наборы dev.

Что проверили на каждой стадии:
- строка `setup`: `engine unsloth dtype bf16 ... trainable_dtype float32`;
- со второй стадии строка `init from runs/local/<предыдущая>`;
- loss на обучении падал;
- T от 0.5 до 3 (у всех пяти стадий);
- у 4-skills и round2: `saved .../merged (186 merged weights)` и все 12 проверок целостности `ok`, `integrity ok`;
- `nan`, `out of memory` и traceback в логах нет.

Память: пик за весь прогон 6.4 из 8 GB (вместе с ~2.5 GB, которые держит Windows), на финальной оценке стадии
documents, где самые длинные тексты. Обходной флаг `--max-state 4096` не понадобился.

## Что заметили (для H100)

- **Ранний лучший чекпоинт.** На 3–4 стадиях из 5 лучший NLL на dev был уже на шагах 50–150. На 1000 записях это
  начало переобучения; на полных данных посмотреть, повторится ли.
- **T на стадии documents = 2.54**, близко к верхней границе 3. На H100 проверить, что не выходит за 3.
- **Предупреждение `causal_conv1d ... falling back`** во всех логах. Замерили: эта свёртка занимает не больше ~10%
  времени шага (на 256 токенах — в пределах шума). Готовых сборок пакета под torch 2.14 нет, сборка из исходников
  требует CUDA Toolkit. Решили не ставить.
- **Время.** Гайд обещал около часа на обучение, вышло около 1 ч 50 мин (22:22 → 00:10). Больше всего — 4-skills
  (~20 мин) и итоговые оценки на полном dev.
- **Память для H100 менять не нужно.** Реальную память и скорость 4B покажет фаза замера времени на H100.
- **`locks/models.json`** получил запись для qwen3.5-0.8b (отпечатки её файлов). Ещё не закоммичена.
